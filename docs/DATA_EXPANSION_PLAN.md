# 法律知识库数据源扩充方案

## 目标
将法律知识库从当前的 143 条扩充到 **1 亿+** 条法律条文/案例

## 数据源清单

### 1. 裁判文书网 (wenshu.court.gov.cn)
- **数据量**: 1.3 亿+ 裁判文书
- **数据类型**: 判决书、裁定书、调解书
- **爬取难度**: 中等（需要反爬虫处理）
- **预计时间**: 3-6 个月（持续爬取）
- **实现状态**: ✅ 已完成爬虫框架

### 2. 中国法律法规信息网 (pkulaw.com)
- **数据量**: 100 万+ 法律法规
- **数据类型**: 法律、行政法规、地方性法规、司法解释
- **爬取难度**: 低（公开数据）
- **预计时间**: 1-2 周
- **实现状态**: ⏳ 待实现

### 3. 国家知识产权局 (cnipa.gov.cn)
- **数据量**: 5000 万+ 专利
- **数据类型**: 发明专利、实用新型、外观设计
- **爬取难度**: 中等
- **预计时间**: 2-3 个月
- **实现状态**: ⏳ 待实现

### 4. 中国市场监管行政处罚文书网
- **数据量**: 1000 万+ 行政处罚案例
- **数据类型**: 行政处罚决定书
- **爬取难度**: 低
- **预计时间**: 1 个月
- **实现状态**: ⏳ 待实现

### 5. 最高法指导案例
- **数据量**: 200+ 指导案例
- **数据类型**: 指导性案例、公报案例
- **爬取难度**: 低
- **预计时间**: 1 周
- **实现状态**: ⏳ 待实现

### 6. 地方性法规数据库
- **数据量**: 50 万+ 地方性法规
- **数据类型**: 各省市地方性法规
- **爬取难度**: 中等（需要逐个省份爬取）
- **预计时间**: 2-3 个月
- **实现状态**: ⏳ 待实现

### 7. 法律学术论文 (CNKI)
- **数据量**: 1000 万+ 论文
- **数据类型**: 法学论文、案例分析
- **爬取难度**: 高（需要付费账号）
- **预计时间**: 不适用（需要合作）
- **实现状态**: ❌ 暂不实现

## 实施计划

### 阶段 1: 快速扩充 (1-3 个月)
**目标**: 达到 1000 万条

1. **法律法规信息** (100 万条)
   - 爬取 pkulaw.com 公开数据
   - 结构化入库
   - 预计时间: 2 周

2. **裁判文书网数据** (500 万条)
   - 持续爬取 wenshu.court.gov.cn
   - 优先爬取近 5 年的案例
   - 预计时间: 2 个月

3. **行政处罚案例** (500 万条)
   - 爬取市场监管处罚文书
   - 预计时间: 1 个月

### 阶段 2: 深度扩充 (3-6 个月)
**目标**: 达到 5000 万条

1. **继续爬取裁判文书** (3000 万条)
   - 扩大爬取范围
   - 优化爬虫性能
   - 预计时间: 3 个月

2. **专利数据** (1000 万条)
   - 爬取国家知识产权局数据
   - 预计时间: 2 个月

3. **地方性法规** (500 万条)
   - 爬取各省市地方法规
   - 预计时间: 2 个月

### 阶段 3: 全面覆盖 (6-12 个月)
**目标**: 达到 1 亿+ 条

1. **继续爬取裁判文书** (5000 万条)
   - 爬取全部历史数据
   - 预计时间: 6 个月

2. **其他数据源** (3000 万条)
   - 仲裁案例
   - 公证文书
   - 法律援助案例
   - 预计时间: 6 个月

## 技术架构

### 爬虫集群
```
爬虫调度器 (Scheduler)
    ├─ 裁判文书爬虫 (10 个实例)
    ├─ 法律法规爬虫 (5 个实例)
    ├─ 专利数据爬虫 (5 个实例)
    └─ 行政处罚爬虫 (3 个实例)

数据存储
    ├─ 原始数据 (JSON 文件)
    ├─ PostgreSQL (结构化数据)
    └─ Milvus (向量数据)
```

### 数据处理流水线
```
爬取 → 清洗 → 结构化 → 向量化 → 入库
  │       │        │          │        │
  ↓       ↓        ↓          ↓        ↓
JSON   去HTML   提取字段   BGE-M3   PostgreSQL
文件   去特殊符   分词标签   嵌入     Milvus
```

## 性能优化

### 爬虫优化
1. **分布式爬虫**: 使用 Scrapy-Redis 实现分布式爬取
2. **代理池**: 使用代理 IP 避免被封
3. **断点续传**: 支持中断后继续爬取
4. **去重机制**: 使用 Bloom Filter 去重

### 存储优化
1. **分区策略**: 按案件类型分区存储
2. **索引优化**: 使用 HNSW 索引加速查询
3. **缓存策略**: 使用 Redis 缓存热点查询
4. **压缩存储**: 对文本数据进行压缩

### 查询优化
1. **预过滤**: 在向量搜索前先过滤
2. **批处理**: 批量查询提高吞吐量
3. **异步查询**: 使用异步 API 提高并发
4. **结果缓存**: 缓存常见查询结果

## 风险评估

### 法律风险
1. **数据版权问题**: 裁判文书属于公开数据，可以爬取
2. **隐私保护**: 需要对个人信息进行脱敏处理
3. **使用限制**: 仅用于法律研究和公共服务

### 技术风险
1. **反爬虫**: 需要持续更新反爬虫策略
2. **数据质量**: 需要严格的数据清洗和验证
3. **存储容量**: 需要预留足够的存储空间

### 运营风险
1. **数据更新**: 需要持续爬取新数据
2. **系统稳定性**: 需要保证 7x24 小时运行
3. **成本控制**: 需要控制硬件和人力成本
