## 二、商业化 AI 法律产品的真实形态（联网调研结论）

一个能「收费落地」的法律 AI 产品，与当前 demo 的差距不在「回答问题的按钮」，而在于从「能回答」升级到「能办成事」，具体为六个维度：

1. **合同全生命周期**：起草 → 审查 → 版本比对 → 归档，形成闭环，而非单次问答。
2. **诉讼支持**：证据清单、庭审准备、类案比对、裁判预测，输出可入卷的可读文书。
3. **合规风险管理**：法规动态跟踪（每日增量）、企业风险自动排查、违规项分级。
4. **多智能体协同**：检索 Agent、起草 Agent、审查 Agent、合规 Agent 像律师团队一样分工，由编排层调度。
5. **数据安全与私有化部署**：律所/企业要求「数据不出内网」，需要私有化交付 + 权限体系 + 审计日志 + 等保合规。
6. **个性化定制**：接入企业自有知识库、合同模板、业务流程，才能真正产生价值并支撑客单价。

这六项中，当前 demo 已有雏形（contract/litigation/compliance/enterprise 路由 + 三层上下文 + MCP + skills），但深度不足，属于「有框架、缺血肉」。

## 三、数据扩充：从 190 万 → 1 亿+ 的真实路径（关键且需诚实）

### 3.1 诚实结论
**仅靠开源数据集无法达到 1 亿条「优质、可商用」法律数据。** 这是本质约束，必须说清楚：

| 数据来源 | 记录量级 | 性质 | 获取方式 | 商用授权 |
|---|---|---|---|---|
| 裁判文书网（全国判决） | 1 亿+ | 真实判例（最核心） | 商业授权或官方接口 | 需授权 |
| 威科先行 / 北大法宝 / 无讼判例 / 把手案例 | 数千万~1.5 亿 | 权威法规+判例+期刊 | **商业授权（付费）** | 需签约 |
| 国家法律法规数据库（flk.npc.gov.cn） | 5 万+ 法规文件 | 权威法条（免费公开） | 官方接口/采集 | 公开数据 |
| 开源法律数据集（CAIL、DISC-LawLLM、LaWGPT 等） | ~25M | 训练语料/SFT 问答 | 免费下载 | 多为研究许可 |
| 程序化生成（合成数据） | 理论上亿级 | **非真实数据，不可作为判例依据** | 本地生成 | 自有 |

**要点：**
- 开源数据最多累计 ~2500 万，且大部分是「LLM 训练用 SFT 问答对」，不是「清洗过的法条+真实判例」，不能直接作为检索底库给用户展示出处。
- 上亿「真实、可溯源、可商用」数据 = **必须采购商业数据库授权**（威科先行 / 北大法宝 / 无讼判例 / 把手案例），年费通常 10 万~50 万+，且需企业签约。
- 裁判文书网直接用爬虫大规模抓取存在法律合规风险（robots 限制、反爬、数据权属），商业化产品不应把「爬虫」作为主力来源。

### 3.2 推荐的「三步走」数据策略
1. **先吃免费公开数据**（立即可做，无授权风险）：国家法律法规数据库全部法规 + 现有已下载的开源数据集入库，把 190 万扩到 ~1000 万级。
2. **接入 1~2 家商业数据库**（需你决策+预算，是上亿的唯一现实路径）：优先「威科先行」或「北大法宝」API，按量计费或年度授权，增量同步到本地。
3. **自建增量采集+清洗管道**（已有骨架）：对合法公开的法规更新做每日增量同步，建立去重、字段清洗、质量评分、溯源索引。

## 六、风险与合规提示（商业化前必须正视）
1. **生成内容的合规风险**：法律 AI 输出必须保留强制引用格式「（《XX法》第X条）」，且「未检索到相关法条」时必须明示、禁止编造——本项目已在 prompt + citation_verifier 中实现，需持续在真实数据上回归。
2. **数据权属**：商业判例/法规的再分发权需在授权合同中明确，避免侵权。
3. **数据安全**：律所/企业要求数据不出内网，私有化部署是前提，云 API 调用需告知用户数据出境/外传情况。
4. **合成数据边界**：程序化生成的数据绝不能冒充真实判例/法条展示给用户，必须打标隔离。
