# 法律智能辅助系统 - 技术架构方案

## 一、项目概述

基于简历中周栩的AI Agent开发经验，结合GitHub/Gitee开源法律AI项目，构建一套从原型到商业化的完整法律智能辅助系统。实现 **Harness Engineering → Loop Engineering** 完整闭环。

### 3.3 核心AI Agent设计

#### 3.3.1 法律咨询Agent (LegalConsultAgent)
- **功能**: 基于RAG的法律问答，多轮对话
- **工具**: 法条检索、案例检索、法律概念解释
- **流程**: 用户提问 → 意图识别 → 知识检索 → 推理生成 → 引用输出

#### 3.3.2 合同审查Agent (ContractReviewAgent)
- **功能**: 合同风险识别、条款分析、合规检查
- **工具**: 合同解析、条款比对、风险规则库
- **流程**: 上传合同 → 解析条款 → 风险识别 → 生成审查报告

#### 3.3.3 文书生成Agent (DocumentGenAgent)
- **功能**: 起诉状、答辩状、法律意见书生成
- **工具**: 模板库、事实要素提取、法律推理
- **流程**: 用户描述 → 要素提取 → 法条匹配 → 文书生成

#### 3.3.4 法条检索Agent (LawRetrievalAgent)
- **功能**: 语义检索法条、司法解释、案例
- **工具**: 向量检索 + 关键词检索 + 北大法宝MCP
- **流程**: 自然语言查询 → 语义理解 → 多路召回 → 排序输出

### 3.4 RAG系统设计

```
文档上传 → 文档解析(pdf/docx/txt) → 文本分割 → 向量化 → 存入Milvus
                                                      ↓
用户提问 → 意图识别 → 向量检索 → 重排序 → 上下文组装 → LLM生成
                                                      ↓
                                          知识图谱增强(Neo4j)
```

### 3.5 数据飞轮与闭环回路

```
用户使用 → 行为数据采集 → 数据标注/清洗 → 模型微调 → 效果提升
    ↑                                                         ↓
    └────────── 用户反馈 ← 效果评估 ← 上线部署 ←──────────────┘
```

**Harness Engineering → Loop Engineering 完整闭环:**

1. **Harness Phase (驾驭阶段)**:
   - 原型开发 → MVP验证 → 种子用户获取
   - 核心功能: 法律咨询、合同审查、文书生成

2. **Loop Phase (循环阶段)**:
   - **采集层**: 用户行为日志、对话记录、满意度评分
   - **分析层**: 问题聚类、badcase分析、用户画像
   - **优化层**: Prompt优化、知识库更新、模型微调
   - **反馈层**: A/B测试、灰度发布、效果回归
   - **迭代层**: 周迭代(小优化) + 月迭代(大版本)

## 四、数据库设计

### 4.1 PostgreSQL 核心表

- `users` - 用户表
- `conversations` - 对话记录
- `feedbacks` - 用户反馈
- `documents` - 上传文档
- `contract_reviews` - 合同审查记录
- `generated_docs` - 生成文书
- `user_behaviors` - 用户行为日志

### 4.2 Milvus 向量集合

- `legal_articles` - 法条向量
- `legal_cases` - 案例向量
- `legal_knowledge` - 法律知识库向量
- `user_documents` - 用户上传文档向量

### 4.3 Neo4j 知识图谱

- 实体: 法条、案例、罪名、法院、律师
- 关系: 引用、参照、类似、上诉、推翻
